{% comment %} The question a QuBe Sync run is asking about a record, with a form per choice, or nothing when it isn't asking. Render it on the record's page with its operation's slug: {% load qubesync %}{% qube_question invoice "create_invoice" %} or include it with qubesync.django.question_context(invoice, "create_invoice") in the page's context. It's the open question of the record's latest run of that operation, as Operation.question kept it on the run. Each form posts your user's choice to that run's question route, with its CSRF token, and a record field's box searches through it too, so the API key never reaches the browser. Django escapes everything, and the qube- classes are for your CSS. With django-csp, the scripts carry request.csp_nonce. A rows field is qubesync/_question_rows.html, the search script qubesync/_question_script.html. This is QuBe Sync's copy, updated with the package.
